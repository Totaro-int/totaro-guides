# AI 에이전트 개발 · 구축 방법 — RAG · 챗봇 · 업무 자동화를 실제로 만드는 순서와 사례

> 이 글은 토타로(TOTARO) 홈페이지의 가이드 원문을 옮긴 것입니다. 원문과 최신 갱신본: https://www.totaro.co.kr/guide/ai-agent-development

AI 에이전트는 대규모 언어 모델(LLM)이 목표를 받아 스스로 추론하고 검색 · 계산 · 외부 시스템 호출 같은 행동을 반복하며 일을 끝내는 소프트웨어입니다. 질문에 답만 하는 챗봇과 달리 도구를 호출해 업무를 수행하며, 회사 데이터를 근거로 답하게 하려면 검색 증강 생성(RAG) 구조를 결합합니다. 구축은 데이터 정제 → 지식베이스 구조화 → 검색 · 생성 설계 → 평가셋 검증 → 실 운영 안착 순서로 진행합니다.

### 챗봇 · RAG · AI 에이전트는 무엇이 다른가
ReAct 패턴은 모델이 '생각 → 행동 → 관찰'을 반복하도록 설계해 에이전트의 기본 구조가 됐고, RAG는 외부 지식을 검색해 생성에 결합함으로써 환각을 줄이고 근거를 제시하게 합니다.
구분 | 하는 일 | 근거 데이터 | 적합한 업무
규칙형 챗봇 | 정해진 시나리오로 응답 | 없음(스크립트) | 단순 안내, 메뉴 선택
LLM 챗봇 | 자연어로 답변 생성 | 모델의 사전 지식 | 일반 질의응답
RAG 챗봇 | 회사 자료를 검색해 근거와 함께 답변 | 사내 문서 · 제품 정보 | 고객 응대, 사내 지식 검색
AI 에이전트 | 추론과 행동(검색 · 계산 · 시스템 호출)을 반복해 과제 수행 | RAG + 업무 시스템 | 견적 매칭, 배합 계산, 초안 생성, 자동 처리

### RAG 구축 5단계

1. 데이터 수집 · 정제 — 제품 정보, 매뉴얼, FAQ, 과거 응대 기록을 모으고 중복 · 구버전을 걸러냅니다. 이 단계가 전체 공수의 가장 큰 부분입니다.
2. 지식베이스 구조화 — 문서를 의미 단위로 자르고(청킹) 임베딩해 벡터 저장소에 넣습니다. 메타데이터(제품, 날짜, 출처)를 붙여 검색 정확도를 높입니다.
3. 검색 · 생성 설계 — 질문에서 조건을 읽어 맞는 문서를 찾고, 근거를 짧게 유지해 모델에 넣습니다. 긴 컨텍스트에서는 중간 정보가 누락되는 현상이 있어 근거를 작게 잘라 넣는 것이 중요합니다.
4. 평가셋으로 검증 — 실제 질문 수십~수백 개로 정답률 · 근거 일치율을 측정하고, 틀린 답을 분류해 데이터나 검색을 고칩니다.
5. 실 운영 안착 — 실 사용자에게 열고 로그를 보며 보완합니다. 운영 체계와 교육을 인계해야 데모에서 끝나지 않습니다.

### 업무 자동화에 AI를 붙일 수 있는 영역

- 고객 응대: 제품 · 주문 문의에 근거 있는 자동 응답(RAG 챗봇)
- 영업 · 매칭: 바이어 조건에 맞는 공급사 · 제품을 대화로 매칭하고 견적 요청으로 연결
- 계산 · 추천: 조건을 읽어 배합 · 견적 · 일정을 계산하는 에이전트
- 문서 처리: 서류 OCR 자동 입력, 판독문 · 보고서 초안 생성
- 콘텐츠: 브랜드 톤에 맞춘 마케팅 문안 · 이미지 생성
- 사내 지식: 규정 · 매뉴얼 검색과 질의응답

### 클라우드 API와 로컬(온프레미스) 중 무엇을 쓰나
데이터가 외부로 나가도 되고 빠르게 시작해야 하면 Gemini 같은 클라우드 API가 유리합니다. 민감한 데이터(의료 · 금융 · 내부 문서)를 다루거나 호출량이 많아 비용이 누적되면 Ollama 같은 로컬 런타임에 경량 모델을 올리는 쪽이 맞습니다. 자주 바뀌는 데이터는 RAG로, 전문 용어와 서식 자체를 모델이 익혀야 하면 fine-tuning(sLLM)으로 다룹니다.

### 실 운영 사례와 기간
토타로가 진행한 사례 기준으로 친환경 용기 자동 배합 에이전트는 약 8주, 삼청당(키토김밥 프랜차이즈) RAG 자동응답 챗봇은 완료됐고, AI 세일즈 비서(공급사 매칭 컨시어지)는 현재 운영 중입니다. 각 사례의 문제 · 해결 · 기술 스택 · 성과는 포트폴리오 상세에 공개되어 있습니다.

**자주 묻는 질문**
Q. AI 에이전트 개발은 어떤 순서로 진행하나요?
A. 진단(어느 업무에 붙이면 효과가 큰지) → 기획(범위와 데이터 확인) → 제작(RAG 구조화, 에이전트 설계, 평가셋 검증) → 안착(실 사용자 운영, 교육 · 인계) 순서입니다. 8주부터 시작하는 주 단위 스프린트가 일반적입니다.

Q. RAG 구축이란 무엇인가요?
A. 회사 문서를 검색 가능한 지식베이스로 만들고, 질문이 오면 관련 문서를 찾아 그 근거로 답을 생성하게 만드는 작업입니다. 모델이 모르는 회사 정보를 근거와 함께 답하게 하는 가장 널리 쓰이는 방법입니다.

Q. 챗봇 개발 비용은 무엇이 결정하나요?
A. 모델 API 비용보다 데이터 정제와 답변 품질 검증 공수가 큽니다. FAQ · 제품 정보처럼 좁은 도메인부터 시작하면 비용과 위험을 줄일 수 있습니다.

Q. 로컬 AI 에이전트 구축은 언제 필요한가요?
A. 의료 · 금융 · 내부 문서처럼 데이터가 외부로 나가면 안 되거나, 호출량이 많아 API 비용이 누적될 때입니다. Ollama 같은 런타임에 경량 모델(sLLM)을 올려 사내에서 서빙합니다.

Q. RAG와 fine-tuning 중 무엇을 써야 하나요?
A. 자주 바뀌는 정보는 RAG, 전문 용어와 서식 자체를 모델이 익혀야 하면 fine-tuning입니다. 둘을 함께 쓰는 경우도 많습니다. 공개 연구에서도 두 방식의 선택 기준이 데이터의 변동성과 전문성에 따라 갈립니다.

Q. AI 업무 자동화 사례에는 무엇이 있나요?
A. 토타로 사례 기준으로 대화만으로 공급사를 매칭하는 AI 세일즈 비서, 친환경 용기 배합을 계산하는 에이전트, 제품 정보를 근거로 답하는 RAG 챗봇, 서류 OCR 자동 입력과 비전 품질 판정을 결합한 수출입 ERP가 있습니다.

Q. AI 에이전트 개발 툴은 무엇을 쓰나요?
A. 사례 기준으로 LangGraph(워크플로), Gemini API(모델), Ollama(로컬 서빙), Supabase(데이터), Next.js(인터페이스)를 과제에 맞춰 조합합니다. 특정 툴을 전제로 하지 않습니다.
