# MVP 개발이란? 단계 · 기간 · 비용 · 외주 선택 가이드 — 최소 기능 제품을 8주 안에 검증하는 법

> 이 글은 토타로(TOTARO) 홈페이지의 가이드 원문을 옮긴 것입니다. 원문과 최신 갱신본: https://www.totaro.co.kr/guide/mvp-development

MVP(Minimum Viable Product, 최소 기능 제품)는 핵심 가설을 검증하는 데 필요한 최소한의 기능만 갖춘 제품으로, 실제 사용자에게 내놓아 반응을 측정하고 다음 개발 방향을 정하는 데 씁니다. 개발은 가설 정의 → 핵심 기능 1~3개 선정 → 설계 → 제작(8주부터) → 출시 · 측정 5단계로 진행하며, 완성도보다 '배포해서 배우는 속도'가 목표입니다.

### MVP 개발 5단계

1. 가설 정의 — 누가, 어떤 문제를, 왜 지금 해결하고 싶어 하는지 한 문장으로 적습니다. 가설이 없으면 MVP가 아니라 작은 완제품이 됩니다.
2. 핵심 기능 선정 — 가설을 검증하는 데 꼭 필요한 기능 1~3개만 남깁니다. 로그인 · 결제 · 관리자도 검증에 필요 없으면 뺍니다.
3. 설계 — 화면 흐름과 측정할 지표(가입 · 재방문 · 전환)를 먼저 정합니다.
4. 제작 — 8주부터 시작하는 주 단위 스프린트로 만들며 중간 결과를 계속 확인합니다. Flutter · Next.js · Supabase 같은 검증된 조합이 속도를 냅니다.
5. 출시 · 측정 — 실제 사용자에게 열고 지표를 보며 다음 범위를 정합니다. 여기서 배운 것이 MVP의 산출물입니다.

### 기간과 비용을 좌우하는 것

- 기능 수: 핵심 1~3개로 제한할수록 기간이 짧아집니다
- 플랫폼: iOS · Android 동시 출시는 크로스플랫폼(Flutter)으로 한 코드베이스 유지
- 연동: 결제 · 지도 · 알림 등 외부 연동 수
- 디자인 범위: 브랜드 완성도보다 흐름 검증에 집중
- 운영: 출시 후 측정 · 수정 주기를 계약에 포함하는지

### 내부 개발 vs 외주

구분 | 내부 개발 | 외주
맞는 경우 | 개발자가 있고 제품이 핵심 역량일 때 | 개발 인력이 없거나 검증 속도가 더 중요할 때
장점 | 제품 지식이 팀에 쌓임 | 8주 안에 배포 가능, 기획 · 디자인까지 한 팀
주의 | 채용 · 온보딩 시간 | 소스 · 문서 인계와 운영 체계를 계약에 포함

### MVP가 실패하는 지점

- 가설 없이 기능부터 나열 → '최소'가 아니라 '작은 완제품'이 됨
- 측정 지표를 출시 후에 정함 → 배운 것이 없음
- 데모에서 멈춤 → 실제 사용자에게 열어야 MVP
- 출시 후 수정 예산이 없음 → 측정 결과를 반영할 수 없음

### 실 운영 앱 사례
토타로가 진행한 NoiseZero 앱은 Flutter로 iOS · Android를 함께 출시했고, ML Kit · Tesseract OCR과 FastAPI · PostgreSQL 백엔드를 결합했습니다. 작업 범위와 기술 스택은 포트폴리오 상세에 공개되어 있습니다.

**자주 묻는 질문**
Q. MVP 개발 기간은 얼마나 걸리나요?
A. 핵심 기능 1~3개 기준으로 8주부터 시작하는 주 단위 스프린트가 일반적입니다. 기능 수, 플랫폼 수, 외부 연동 수가 기간을 늘립니다.

Q. MVP 개발 단계는요?
A. 가설 정의 → 핵심 기능 선정 → 설계(지표 포함) → 제작 → 출시 · 측정 5단계입니다. 출시 후 측정해서 배우는 것이 산출물입니다.

Q. MVP는 어떤 기능까지 넣어야 하나요?
A. 가설을 검증하는 데 꼭 필요한 기능만입니다. 로그인 · 결제 · 관리자 화면도 검증에 필요 없으면 뺍니다. 넣을 기능보다 뺄 기능을 정하는 것이 MVP 기획입니다.

Q. MVP 개발을 외주로 맡겨도 되나요?
A. 개발 인력이 없거나 검증 속도가 더 중요하면 외주가 맞습니다. 다만 소스 코드 · 문서 인계와 출시 후 수정 범위를 계약에 넣어야 다음 단계로 이어집니다.

Q. 앱 MVP는 iOS와 Android 중 무엇부터 만들어야 하나요?
A. 타깃 사용자의 기기 비중을 따르되, Flutter 같은 크로스플랫폼으로 한 코드베이스에서 둘 다 출시하면 선택 자체를 피할 수 있습니다.

Q. MVP 개발 비용은 무엇이 결정하나요?
A. 기능 수, 플랫폼 수, 외부 연동, 디자인 범위, 출시 후 운영 포함 여부입니다. 토타로는 정해진 패키지 요금 없이 30분 무료 진단 후 단계별 견적을 드립니다.
